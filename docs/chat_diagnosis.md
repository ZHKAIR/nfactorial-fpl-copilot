# Диагностика чата FPL Copilot (23.09.2026)

> **Статус 24.09:** план P0–P3 реализован (промпты v4, история, новые интенты, валидатор) — результаты
> и не достигнутое: `docs/EVALS.md` §9, `docs/agent.md` «Чат v4».

Только диагностика: существующие файлы проекта не менялись. Прогон — через настоящий агент так же,
как его вызывает страница чата (`app/views/5_chat.py`), менеджер 895045, стратегия balanced.
Номера строк — рабочего дерева на 18:52 UTC (соседние агенты продолжают править `graph.py`,
`validate.py`, `resolve.py`, промпты v3 — строки могут сдвинуться).

## 1. Главный вывод

Чат слабый по четырём структурным причинам, а не из-за «плохого промпта» в целом.

1. **Пользователь видит старый код.** Streamlit на :8501 запущен в 15:33 UTC — до того, как в
   `config.py` дефолт `agent_prompt_version` сменили с v2 на v3. `settings` читаются один раз при
   импорте, поэтому чат владельца работает на роутере и объяснителе **v2** и старом графе. Все три
   треда со скриншотов (18:09–18:12 UTC) в чекпоинтах помечены `prompt_version=v2`. Ни одна
   сегодняшняя правка (правило «слабые места» → `transfer`, транслит кириллических имён,
   `candidate_news`) пользователю не видна до перезапуска. На v2 ложных отказов 16/55, на v3 10/55.
2. **У чата нет памяти.** Каждое сообщение — новый тред, в роутер и объяснитель уходит только
   текущая строка. Уточнения «ты про gw7?», «а он сколько наберёт?», «почему не Салах?» читаются
   как самостоятельные вопросы и отклоняются. Из 7 многоходовых строк 6 — «криво», 1 — «частично».
3. **Закрытый список из 11 интентов, где `off_topic` служит корзиной, плюс статичный английский
   отказ.** Нет интентов для прогноза очков игрока, календаря и соперников, фишек моего состава,
   фактов тура (дедлайн), цен и трендов, общего «что мне делать». Всё, что не похоже на шаблоны,
   уходит в `off_topic`, а отказ — фиксированная английская строка без LLM. Например, «сколько
   очков наберет Haaland в следующем туре?» отклонён с причиной роутера «predicting points is
   off-topic for FPL». На русском написан 1 отказ из 15.
4. **Ближайший инструмент + жёсткий шаблон объяснителя + узкий валидатор.** Если вопрос не
   совпадает с интентом, роутер берёт ближайший, и инструмент считает не то: состав — всегда на
   ближайший тур, план — без фишек, рейтинг — только по прошлому. Объяснитель обязан пересказать
   `headline` по фиксированной таблице интента и добавить обязательные пункты новостей. Своими
   знаниями пользоваться нельзя, поэтому разрыв заполняется выдуманными связками: «3-5-2
   максимизирует очки скамейки для Bench Boost», «лучший календарь у Gvardiol», «rated 6 out of
   10», XI на GW6 подписан как GW7, капитан переворачивается с Saka на Haaland. Валидатор проверяет
   только десятичные числа и латинские имена. Итог: 26 из 60 ответов «криво», а предупреждение
   валидатора показано лишь в 2 из 43.

## 4. Причины в коде

**Операционное: UI на старом коде и v2.**
- `src/fplcopilot/config.py:140` — `agent_prompt_version: str = "v3"` (в HEAD было `"v2"`);
  процесс Streamlit PID 43763 запущен в 15:33 UTC, `settings` читаются при импорте, агент
  кешируется `st.cache_resource` (`app/common.py:64-66`). Пример: треды 18:09 / 18:10 / 18:12 —
  `prompt_version=v2`. В футере UI версия промпта не видна, поэтому это нельзя было заметить.

**Нет истории диалога.**
- `app/views/5_chat.py:29-34` — `run_agent` передаёт только `prompt`, `manager_id`, `strategy`,
  `squad_override`; история `st.session_state[CHAT_KEY]` используется только для отрисовки.
- `agent/graph.py:3096` — `thread_id = thread_id or new_thread_id()`: каждое сообщение — новый тред.
- `agent/llm.py:314-321` — у `RouterRequest` нет поля истории; `llm.py:329-334` — сообщение
  роутеру = `Query:` + контекст тура.
- `agent/llm.py:349-358` — у `ExplainRequest` тоже нет истории.
- `agent/graph.py:587-594` — роутер получает только `state["query"]`.
- Пример: c52 «ты про gw7?» → `off_topic`, reason «not related to FPL».

**Таксономия и отказ.**
- `agent/state.py:16-28` — 11 интентов.
- `agent/prompts/v3/router.system.md:10-45` — описания узкие:
  - `player_status` (строки 11-13) — только фитнес, прогноз очков не упомянут → c32;
  - нет календаря, фишек моего состава, фактов тура, цен и трендов;
  - `off_topic` (строка 45) сформулирован правильно, но это единственный «прочий» класс, и модель
    использует его как корзину;
  - оценка состава закрыта точечно (строки 18-22) через `transfer`.
- `agent/graph.py:627` — незнакомый интент → `off_topic`.
- `agent/graph.py:707-725` — `refuse` возвращает статичный английский текст без учёта
  `state["language"]` (уточнение, `graph.py:2600`, язык учитывает — механизм есть).
- `agent/graph.py:2815-2818` — `off_topic` сразу ведёт в `refuse`; режима «частичный ответ» нет.
- Модель и температура не причина: `config.py:118-122` gpt-4o-mini, `llm.py:339` T=0, 0
  нестабильных строк из 29 × 5.

**Ближайший инструмент считает не то.**
- `agent/graph.py:1238-1244` — lineup и captain: `OptimizeTeamInput(gw=gw)`, где `gw` — всегда
  ближайший тур; `keep`, `allow_hit` и фишки игнорируются → c19, c20, скриншот №1.
- `agent/graph.py:212-214` — `HORIZON_HINT` принимает «gw7» как явный период, поэтому горизонт 1
  от роутера проходит → c20: план GW6–GW6 для «BB в GW7».
- `agent/graph.py:1381-1394` — `BuildPlanInput(...)` без `chips`, хотя инструмент их умеет
  (`agent/tools.py:404-430`, `PlanChipIn`; UI «План» передаёт их через `app/plan_chips.py:115`).
- `agent/graph.py:1154-1167` — о фишках в фактах есть только `chips_available`: у 895045 это `[]`
  без пояснения «сыграны, снова с GW20»; даты сыгранных фишек (`client.history`) агент не
  получает → c17, c23–c26.
- `agent/llm.py:186-233` — `RankingDraft` описывает только прошлое окно
  (`gw_from` / `gw_to` / `last_n_gws`), будущей метрики по xPts нет. Роутер кладёт «следующие 3
  тура» в `last_n_gws=3` (сырые поля роутера c39 / c40) → F6.
- `agent/graph.py:1596-1604` — `strategy_question` — только KB, без контекста тура и состава →
  c25 (фишки), c49 (дедлайн), c53.
- Готовые данные не подключены к агенту: календарь / FSI (`core/fixtures.py:244` `fixture_views`,
  `app/views/1_squad.py:39` `fixture_run_ranks`), MCP-инструменты `get_player_points_breakdown`,
  `get_team_defensive_profile`, `get_player_advanced_stats` (`mcp_server/server.py:687, 712, 761`).
  `diagnose_squad` вызывается только в `load_context` (`graph.py:551`) как список проблем.
  `transfers_in_event` и цены из bootstrap агент не показывает → c27, c28, c44, c45.
- Резолвер до правки соседей: `git show HEAD:src/fplcopilot/agent/resolve.py`, строки 37-46 —
  токены `[a-z0-9]+`, кириллица не читалась. В рабочем дереве это исправляется (`agent/translit.py`),
  в UI — ещё нет.

**Шаблон объяснителя и валидатор.**
- `agent/prompts/v3/explain.system.md:45-49` — обязательные секции и «Verdict restating
  FACTS.headline»; `53-79` — ровно одна таблица с колонками по интенту.
- `explain.system.md:64-65` — для captain / lineup колонка «Captain points (×2)» у каждого
  игрока → 7.22 со скриншота, c19.
- `explain.system.md:24-27` (HARD RULE 1: только FACTS) в сочетании с обязательными секциями:
  когда FACTS не отвечают на вопрос (GW7, BB), модель не может сказать «этого я не считал» —
  такого правила нет — и додумывает. Скриншот, c20, c30.
- `explain.system.md:142-166` и `agent/llm.py:432` — блок NEWS «REQUIRED in Why»: пункты про
  клубы добавляются даже в ответ «кого продать?» → F10.
- `agent/validate.py:10` — «целые числа не проверяются (GW, ранги, %)» → «GW7», «6 out of 10»
  проходят.
- `validate.py:39-43` — проверяются только заглушки цитат, латинские слова с заглавной и десятичные
  числа. Не проверяются: согласованность вердикта с `headline` (c15, c18) и принадлежность цитаты
  пункту (F9).
- `agent/graph.py:2084` — английская строка `⚠ Validation…` дописывается прямо в ответ;
  `5_chat.py:91-96` — ещё один `st.warning` в футере.
- `agent/graph.py:1997` — фолбэк при сбое LLM: английский вердикт и JSON фактов.
- `agent/graph.py:2618` — подсказка про `--choose` в CLI попадает в чат.

**Откуда странные цитаты и Bench Boost на скриншоте.** Тред `1adca0521448`: вопрос «в gw7 буду
делать bench boost… JOao Pedro не убирать… Платные трансферы — нельзя» → v2 → `lineup`. Посчитан
XI на GW6 без BB, keep и hit. В EVIDENCE — только новости João Pedro, и объяснитель приклеил ту
же цитату `[fpl_api, 16.09]` к пункту про B.Fernandes. «Безопасный» — из тега `captain_tag_rule`
(>30% владения). Рассуждение про 3-5-2 и BB — заполнение обязательного «Why» без фактов о фишке.

Когда появится передача истории: раннер сам передаст `history=`, если у `Agent.stream` есть
параметр `history` (или `messages`). Если API будет другим (например, переиспользование
`thread_id`), нужно поправить одну функцию `call_agent` в `evals/run_chat.py`, чтобы она
по-прежнему повторяла `5_chat.py`. Для многоходовых строк есть `--history replay` — предыдущие
реплики пользователя прогоняются живьём, и в историю попадают настоящие ответы.
